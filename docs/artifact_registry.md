# Artifact Registry

This file tracks all data, model, and report artifacts generated by this project.

## Data Layout

The paths are defined in `src/core/data_paths.py` (`get_data_paths(season)` for season files, module constants for `reference/` and `training/`).

| Folder | Holds |
|---|---|
| `data/reference/` | Cross-season inputs not rebuilt from game logs: `player_metadata.csv` (tracked), `player_movement.csv`, `espn_transactions.csv` |
| `data/season=YYYY-YY/` | One season: `raw/` (game logs, `boxscores/`, play-by-play, starters), `processed/`, `features/`, `analysis/` (rosters, core players, opening Elo, observed affiliation events) |
| `data/training/` | Cross-season model-ready datasets (`team_model_ready_{YYYY_YY}.csv`, `player_model_ready.csv`) and the PBP situational lookup |
| `data/frontend_store/` | SQLite store the API serves to the frontend |
| `data/predictions/` | Shadow prediction log |
| `data/experimental/` | `--output-scope experimental` and `--mock` outputs; production code never reads it |

## Production Artifacts

### Datasets
- `data/training/team_model_ready_{YYYY_YY}.csv` — **ACTIVE TEAM MODEL-READY DATASET (V3)** (2020-21 to 2025-26 for training, plus the in-progress 2026-27 refreshed daily by `--update-data`; rebuilt 2026-10-21 with pre-game `TEAM_CORE_*` features, 206 columns with continuous Elo, Dean Oliver Four Factors, schedule fatigue, deterministic playoff series metadata, and advanced box score features including 3PT regression delta, assist-to-turnover, havoc rate, foul rate, FT margin, block rate, and scoring diet distributions)
- `data/season={YYYY-YY}/raw/player_starters.csv` — Per-game starter flags (`Game_ID, Player_ID, TEAM_ABBREVIATION, IS_STARTER`) from BoxScoreTraditionalV3, appended by `src/ingestion/starters_fetcher.py` during game ingest (games missed by a transient API failure are completed on the next update). Backfilled for 2025-26 only; resume other seasons with `scripts/backfill_starters.py <season>`. Feeds the role-minutes rule in `src/features/starter_history.py` and the `IS_STARTER` badge in the game box score; not a WIN/SCORE model feature (a 2025-26 backtest showed no gain).
- `data/training/player_model_ready.csv` — **ACTIVE PLAYER MODEL-READY DATASET (V4)** (6 seasons, 165,988 rows; rolling/EMA form, usage, opponent allowance per position group, rest. CSV only: the stale parquet copy was removed on 2026-10-20 because nothing refreshed it)
- `data/season={YYYY-YY}/features/team_features.csv` — Season-scoped pre-game team features
- `data/season={YYYY-YY}/features/player_features.csv` — Season-scoped individual player features
- `data/season={YYYY-YY}/processed/pbp_stints.csv`, `pbp_player_games.csv`, `pbp_game_quality.csv` — **EXPERIMENTAL** lineup stints (ten-player lineup, seconds, points for/against), per-player on-court seconds and margin, and a per-game box score check (`USABLE` flag). Built from cached play-by-play by `scripts/build_pbp_lineups.py --season YYYY-YY` (`src/processing/pbp_lineups.py`; no API calls); `src/features/player_impact.py` fits ridge player impact from the stints. Not read by production
- `data/season={YYYY-YY}/analysis/core_players.csv` — Source of truth for the season's team core rotations (written by `--run-roster-analysis`)
- `data/season=2026-27/analysis/team_elo_initial.json` — **ACTIVE 2026-27 OPENING ELO RATINGS** (Chained multi-season continuous Elo across 2020-2026, regressed by 25% towards 1500 with offseason roster talent turnover adjustments)


### Frontend Data Caches
- `data/frontend_store/season_{YYYY_YY}.db` + `global.db` — **FRONTEND STORE**, the only data source of the frontend (served by `src/api/services/frontend_data.py` under `/frontend-data-api/*`). Built by `scripts/build_frontend_store.py` (`src/frontend_store/`) from `data/`: games feed, box scores, game details, player game logs/averages, PBP moments, rosters, movers; global: seasons, player profiles, season averages, trades. A season is sealed when its Finals are decided (`meta.status = closed`) and skipped afterwards unless `STORE_VERSION` changes or `--force` is passed. Not tracked in git.
- `data/season=YYYY-YY/raw/play_by_play/{GAME_ID}.json` — Source-of-truth structured play-by-play cache generated by `scripts/build_play_by_play.py`; includes quarter scores, enriched event rows, running player totals, assist metadata, and highlight badges. Current coverage is Finals-only for seasons already backfilled.
- `data/season=YYYY-YY/analysis/team_rosters_live.csv` — Display-only in-season roster built by `src/analysis/live_roster_refresh.py` (bootstrap `team_rosters.csv` + current regular-season logs, `STATS_SEASON` column). Consumed by the frontend store (Team Explorer, player profiles). Models and `src/api/services/player_projection.py` keep reading `team_rosters.csv`. Refreshed by `--update-data` (Step 9b), live game refresh, or `scripts/refresh_current_season_views.py --season YYYY-YY`.

### Models

**Release: v11** (`release:` in `config/production_artifacts.yaml`). Artifact file names carry no version; one release number covers the WIN, SCORE and PLAYER models and is stamped into each `*_metadata.json` (`version`), which the API returns as `model_version` and the frontend shows. To retrain, bump `release` in `config/training_manifest.yaml`: `scripts/retrain_pipeline.py` refuses to retrain under the live release and writes the new one to the production manifest on promotion. Until 2026-10-21 the models were named by generation (win/score v10, player v9); the old labels survive as `legacy_version` in the metadata.

- `models/production/win_model.pkl` — **ACTIVE PRODUCTION WIN MODEL** (uncalibrated logistic regression, 8 features: ELO_DIFF, IS_HOME, CLEAN_NET_RTG_DIFF_LAST_10, WINRATE_DIFF_LAST_10, REST_DIFF, IS_B2B, OPP_IS_B2B, ABS_DIFF roster availability; chosen by expanding-window Brier over LightGBM and L1 logistic)
- `models/production/win_features.json` — WIN inference feature list (8 features, see `config/features/win.yaml`)
- `models/production/win_metadata.json` — WIN model metadata (2025-26 holdout: 68.6% Acc, 0.753 AUC, 0.2017 Brier, from the copy fitted without 2025-26; the shipped model is refit on 2025-26 too; walk-forward 2021-22..2025-26: 65.6% Acc, Brier 0.2141 vs 0.2157 for Elo + home court; 2025-26 is the easiest of those seasons)
- `models/production/score_model_home_rtg.pkl` — **ACTIVE PRODUCTION SCORE HOME RTG** (standardized RidgeCV on OFF_RTG_LAST_10 and OPP_DEF_RTG_LAST_10)
- `models/production/score_model_away_rtg.pkl` — **ACTIVE PRODUCTION SCORE AWAY RTG** (standardized RidgeCV on OFF_RTG_LAST_10 and OPP_DEF_RTG_LAST_10, away-team rows)
- `models/production/score_model_pace.pkl` — **ACTIVE PRODUCTION SCORE PACE** (standardized RidgeCV on PACE_LAST_10 and OPP_PACE_LAST_10)
- `models/production/score_model_margin.pkl` — **ACTIVE PRODUCTION SCORE MARGIN** (standardized RidgeCV on the WIN model's inputs; target is the actual final margin)
- `models/production/score_model_ridge_total.pkl` — SCORE Ridge total residual correction (playoff / back-to-back / rest indicators, fit on temporal OOF residuals against actual points)
- `models/production/score_model_ridge_margin.pkl` — SCORE Ridge margin residual correction (same indicators)
- `models/production/score_metadata.json` — SCORE metadata (trained 2020-21..2025-26; walk-forward 2021-22..2025-26 total MAE 14.90 vs 14.95 for a last-10 points baseline, margin MAE 10.97 vs 11.41; intervals from actual-point OOF residuals, overtime included)
- `models/production/player_model_pts.pkl` — **ACTIVE PRODUCTION PLAYER PTS** (LightGBM, L1 objective)
- `models/production/player_model_reb.pkl` — **ACTIVE PRODUCTION PLAYER REB** (LightGBM)
- `models/production/player_model_ast.pkl` — **ACTIVE PRODUCTION PLAYER AST** (LightGBM)
- `models/production/player_features.pkl` — PLAYER inference feature list (21 features from `config/features/player.yaml`; position flags and opponent allowance come from `add_player_matchup_features`)
- `models/production/player_metadata.json` — PLAYER metadata (trained 2020-21..2025-26; 2025-26 holdout MAE PTS 4.51 / REB 1.89 / AST 1.33 vs EMA-10 4.61 / 1.92 / 1.35; the Ridge residual correction was retired on 2026-10-20 because it raised PTS MAE every season)
- `models/production/clean_holdout_metrics.json` — 2025-26 metrics of the holdout copies (fitted without that season) recorded at promotion; the retrain gate compares challengers against these
- `config/features/win_base_columns.json` — Base feature list that `config/features/win.yaml` reads (`base_feature_file`); not a model
- `models/production/leakage_clean_release.json` — Record of the 2026-10-04 leakage-clean promotion, written by `scripts/retrain_pipeline.py`
- `models/experimental/holdout_eval/` — Holdout copies of the production WIN/SCORE/PLAYER models fitted without 2025-26; use with `NBA_MODEL_DIR=models/experimental/holdout_eval` for honest 2025-26 replays

Only these files are kept under `models/` (cleaned 2026-10-21). Retired generations (V8 archive, `v9` win/score aliases, promotion backups, `replaced_leaky/`) were deleted; the tracked ones remain in git history. `retrain_pipeline.py` writes new candidates to `models/experimental/` and a backup under `models/production/backup/<run_id>/` on each promotion.

### Evaluation & Benchmarks
- `reports/evaluation/multi_season_walk_forward_backtest.md` (and `.json`) — **ACTIVE MULTI-SEASON WALK-FORWARD BACKTEST** (5 unseen seasons 2021-22..2025-26; production WIN/SCORE/PLAYER configurations against Elo + home court, last-10 real points and EMA-10 baselines; regenerate with `python -m scripts.walk_forward_benchmark`)
- `reports/backtests/2026-10-22_recency_weight/` — **ACTIVE** recency-weight experiment (`README.md`, `code/recency_weight_exp.py`): exponential season down-weighting for WIN/SCORE/PLAYER, no gain at any half-life 0.5-4 years; production keeps equal weights; also history length (flat after 3 seasons) and travel/time-zone/altitude features (no gain); player rating comparison for ABS_DELTA (Game Score stays: FANTASY equal, IMP and plus-minus ratings no better)
- `docs/early_season_transitions.md` — **ACTIVE** description of how WIN, SCORE and PLAYER hand over from last season's prior to current-season form (weights, windows, code entry points)
- `reports/backtests/2026-10-23_win_metadata_check/` (and `_prev`) — **ACTIVE** walk-forward re-run with the 8-feature WIN model (`README.md`, per-game predictions); source of the README walk-forward table
- `reports/backtests/2026-10-23_prior_floor/` — **ACTIVE** prior-floor test (`README.md`, `code/`): a 5-10% Elo / prior share after the hand-over does not help WIN (identical log loss) and gains 0.1-0.2% for PLAYER; shipped only the prior reliability scaling by last season's games played
- `reports/backtests/2026-10-23_opportunity_features/` — **ACTIVE** box score opportunity features for PLAYER (`README.md`, `code/opportunity_exp.py`): rebound/assist/shot-use rates x expected game environment add only 0.0064 PTS, 0.0015 REB, 0.0002 AST MAE; not adopted, tracking data not fetched
- `reports/backtests/2026-10-21_early_season/` — **ACTIVE** early-season transition backtest (`README.md`, reproducible scripts in `code/`, outputs in untracked `data/experimental/early_season/`): SCORE prior-to-form hand-over, window lengths, margin vs Elo, PLAYER prior blend, season-start roster availability
- `reports/backtests/2026-10-20_review/` — offline walk-forward (`metrics.json`, per-season prediction parquets for 2023-24..2025-26) and the 2025-26 live replay through the API code with holdout models (`live_2025_26.parquet`: AUC 0.735, Brier 0.206, total MAE 15.46, margin MAE 11.42, 0 failures)
- `data/predictions/paper_ledger_{YYYY_YY}.jsonl` — **APPEND-ONLY PAPER TRADING LEDGER** (one frozen pre-game WIN + SCORE prediction per regular-season/playoff game, first write wins, written by `scripts/paper_trading_snapshot.py --season YYYY-YY [--date YYYY-MM-DD]` before tip-off; outcomes are joined from `raw/team_games.csv` at read time by `src/api/services/paper_trading.py` and served at `/frontend-data-api/paper-trading` for the frontend Paper Trading tab. Started with 2026-27; `--backfill [--through DATE]` adds already-played games as-of their date (`origin: backfill`, features use only earlier games, shown with a Backfill badge); live records created after tip-off are flagged and excluded from metrics. Live records also freeze `injury_report` (official NBA injury report used for the prediction: publish time, which teams had filed, players listed); statuses become model overrides via `src/ingestion/nba_injury_report.py` (Out 0, Doubtful 0.25, Questionable 0.6 placeholders, Probable 0.9). Unlike the shadow log, it never holds preseason, bootstrap or repeated rows)
- `data/season=YYYY-YY/raw/injury_history.csv` — **INJURY HISTORY** (final official NBA injury report of each past game day, one row per listed player; days with nobody listed are marker rows with status `NONE`). Written by `src/api/services/injury_history.py` when the Injuries tab or its endpoint `/frontend-data-api/injuries` is used (at most every 30 minutes, 14 days per sync, missing days are probed from the NBA PDF archive). Current season only, local, not published to the cloud.
- `data/predictions/shadow_predictions_log.jsonl` — **APPEND-ONLY SHADOW PREDICTION STORE** (Structured log with prediction_id, model version, timestamp, conformal ranges, and feature snapshots).
